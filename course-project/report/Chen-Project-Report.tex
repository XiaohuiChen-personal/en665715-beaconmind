\begin{abstract}
Language-model agents now plan for robots and call their tools, but the robot's pose and map still come
from classical estimators. BeaconMind asks whether a large language model (LLM) can own landmark
simultaneous localization and mapping (SLAM) itself. A small differential-drive car with wheel encoders,
an inertial measurement unit and one camera explores a walled arena whose only landmarks are AprilTags,
some of which share an ID. At every stop a stateless ReAct agent receives the odometry increment and the
tag detections as text, calls deterministic single-timestep geometry tools, and decides which detections
to trust, which beacon each belongs to, and which pose and map to report; a validator below the model
checks every move. The study will compare the agent with dead reckoning, a factor-graph reference and the
same procedure written as code, on identical replayed logs and in closed loop, using trajectory, map and
association error, tool-call F1 against the coded procedure, and a rubric for the agent's notes scored by
LLM judges calibrated without hand labels. A pilot
with Claude Opus 5.5 on five simulated episodes per condition (\stepsNom{} and \stepsDrift{} steps)
found that the agent executed the procedure almost exactly (tool-call F1 \fOneNom{} and \fOneDrift{}).
Without odometry drift it did not beat dead reckoning (median trajectory error \ateLTwoNom{} versus
\ateBZeroNom{}\,cm); with a 2\,\% systematic odometry error the order reversed (\ateLTwoDrift{} versus
\ateBZeroDrift{}\,cm). These are pilot results without significance claims; they made odometry drift a
blocked factor of the main study.
\end{abstract}

\section{Introduction}\label{sec:intro}
Agentic language models now drive robots through tools: they decompose instructions into admissible
skills~\cite{ahn2022saycan}, close the loop with textual feedback~\cite{huang2023inner}, and interleave
reasoning with actions~\cite{yao2023react}, and frameworks such as ROSA expose the Robot Operating System
(ROS) to such agents~\cite{royce2025rosa}. These systems take the robot's state, its pose and its map, as given
or from a classical estimator. Diagnostics of LLM spatial reasoning explain the caution: models
treat spatial questions in isolation~\cite{li2026llms}, collapse on long whole-route plans~\cite{jiang2026lost},
and make arithmetic mistakes even when their decomposition is right~\cite{gao2023pal}. Tools remove the
arithmetic; what remains open is whether the \emph{decisions} of an estimator, which detection to trust,
which landmark a detection belongs to, and whether a pose fix or a loop closure is accepted, can be owned
by a language model. If they can, an agent can explain, question and refuse on the basis of its own state;
if they cannot, the boundary of agentic control in robotics is clearer.

\textbf{Goal.} BeaconMind's ReAct agent must keep its own pose belief and AprilTag map on a small car well
enough to explore a walled arena, return to its start and drive to a named beacon, while a deterministic
validator keeps every move bounded and safe. Tag IDs may repeat, so data association is not given by the
tag code.

\textbf{Contributions.} (1)~A tool-grounded, stateless ReAct agent design in which the LLM owns every SLAM
decision, single-timestep tools compute every geometric quantity, and a validator below the model enforces
safety (Section~\ref{sec:system}); the code is public. (2)~An evaluation protocol that separates estimation
(identical replayed logs) from navigation (closed loop), compares the agent with three baselines, scores
metrics on a 0--1 scale where possible, measures tool-call F1 against the coded procedure applied to the agent's own
input, and scores the agent's free-text notes with a rubric whose two LLM judges are calibrated without
hand labels (Section~\ref{sec:experiments}). (3)~A pilot that measured procedure fidelity, latency and cost,
and showed that the answer to the primary question depends on odometry drift (Section~\ref{sec:results}).

\textbf{Research questions.} The primary question, RQ1, is whether the agent's pose belief is more accurate
than dead reckoning and how close it comes to a factor-graph reference. RQ2 asks how precisely the agent
associates detections when tag IDs repeat, and how faithfully it executes the procedure. RQ3 asks whether,
in closed loop, it returns to the start and reaches named beacons as often as the procedure written as code.

\textbf{Roadmap.} Section~\ref{sec:related} reviews related work, Section~\ref{sec:system} describes the
system, Section~\ref{sec:experiments} specifies the experiments, Section~\ref{sec:results} reports the pilot,
and Section~\ref{sec:conclusion} concludes.

\section{Related Works}\label{sec:related}
\subsection{Language-Conditioned Planning and Closed-Loop Agents}
LLM plans for household tasks are plausible but often not admissible~\cite{huang2022zeroshot}; SayCan grounded
each skill with a learned affordance value, without which planning success fell from 84\% to
67\%~\cite{ahn2022saycan}. Inner Monologue showed that closed-loop textual feedback significantly improves
completion~\cite{huang2023inner}, and ReAct's interleaving of reasoning, action and observation beat imitation
and reinforcement learning on ALFWorld and WebShop by 34 and 10 points~\cite{yao2023react}. Kambhampati
\textit{et~al.} argue that LLMs can neither plan nor verify plans alone and should propose candidates that sound
external verifiers check~\cite{kambhampati2024llmmodulo}. ROSA packages a ReAct agent with ROS
tools~\cite{royce2025rosa}, an agentic interface in the classification of Salimpour
\textit{et~al.}~\cite{salimpour2025towards}. Failures remain: in the Embodied Agent Interface, trajectory-feasibility
errors are common (45.2\%)~\cite{li2024embodied}, and the most safety-conscious agent of
SafeAgentBench rejects only 10\% of detailed hazardous tasks~\cite{yin2025safeagentbench}. BeaconMind adopts one
admissible move per observation, a closed loop, and, following LLM-Modulo, a deterministic validator between the
model and the motors. It differs in what the model reasons about: these works plan tasks and take the robot's
state as given, while BeaconMind asks the model to estimate that state.

\subsection{Language Models in Navigation, Mapping, and SLAM}
In the language-driven navigation systems reviewed here the geometry stays classical (Table~\ref{tab:division}):
the pose comes from odometry, SLAM or a pre-built scene graph, and the model plans over the graph, scores or selects
frontiers, or picks goals~\cite{rana2023sayplan,yokoyama2024vlfm,yu2023l3mvn,lee2026spatial}. The closest system
identified in the literature search, by Syarubany \textit{et~al.}, issues one constrained command per junction
with AprilTags as anchors but takes its global pose from ORB-SLAM3~\cite{syarubany2026llm}.
Where language models come closer to SLAM they supply semantics or discrete choices: SEO-SLAM's agents verify,
relabel and merge object landmarks while association is a linear assignment and the map comes from a factor
graph~\cite{hong2025seoslam}; Lyu \textit{et~al.} let a multimodal LLM choose among place-recognition
candidates~\cite{lyu2024tell}; and Sandfuchs \textit{et~al.} state of their gridworld controllers that
``this is not SLAM: the uncertainty is in the map, not in pose''~\cite{sandfuchs2026llms}. Learned policies
such as NoMaD avoid metric estimation altogether~\cite{sridhar2024nomad}. In none of these systems is the pose
estimate in the model's hands, and to my knowledge no prior study reports a trajectory or map error for a
landmark-SLAM estimate maintained by an LLM; that measurement is the gap this project targets.

\subsection{Limits of LLM Spatial Reasoning and the Case for Tools}
Jiang \textit{et~al.} find that whole-route maze navigation by GPT-4o and others falls to near-zero success by
$10\times10$ mazes, that structured coordinate text is the most navigable input, and that handing corridor
walking and dead-end retreat to a deterministic walker, with the model queried only at junctions through an
explicit cell-type prompt, lifts GPT-4o's success by up to 92 points at mid sizes, although the collapse returns by
$30\times30$~\cite{jiang2026lost}. Li \textit{et~al.} show that accuracy depends on the representation:
Gemini-2.5-Flash with chain-of-thought prompting reaches 80--86\% on small mazes given as adjacency lists but
16--34\% on character grids~\cite{li2026llms}. Deng \textit{et~al.} find that the best vision-language
model reaches a macro-F1 of 0.66 on relative camera pose, against 0.99 for a geometric pipeline~\cite{deng2026lost},
and PAL shows that LLMs decompose problems well but make arithmetic mistakes, and that off-loading the solution
step to an interpreter is more accurate than much larger models~\cite{gao2023pal}. BeaconMind follows these
findings: detections arrive as structured text, every geometric quantity comes from a tool restricted to one
timestep, the system prompt prescribes a per-step procedure (predict, associate, correct, update the map, check
loop closure, decide), and each step is posed as an isolated decision, which Jiang \textit{et~al.} found more
reliable than the same decision inside a long plan.

\subsection{Fiducial Landmark SLAM and Evaluation Practice}
AprilTag gives a tag's identity and full six-degree-of-freedom pose from one image~\cite{olson2011apriltag}; TagSLAM builds a factor
graph over tags and notes that ``loop closure is guaranteed once a tag is successfully
decoded''~\cite{pfrommer2019tagslam}, and iSAM2 solves such graphs incrementally~\cite{kaess2012isam2}. Sturm
\textit{et~al.} formalize the absolute trajectory error (ATE) and relative pose error~\cite{sturm2012benchmark},
and Anderson \textit{et~al.} recommend an explicit DONE action and success weighted by path length
(SPL)~\cite{anderson2018evaluation}. BeaconMind uses a GTSAM/iSAM2 graph as its best-case reference, dead
reckoning as its floor, and removes the assumption that makes association trivial in TagSLAM: some IDs are
duplicated on purpose.

\subsection{Evaluating LLM Agents: Metrics, Judges, and Statistics}
HELM argues for reporting several metrics side by side instead of accuracy alone~\cite{liang2023holistic}, which
BeaconMind follows with pose, map, association, tool-use, text-quality and cost metrics. Tool calls are scored in
the spirit of Gorilla and the Berkeley Function Calling Leaderboard, which match the structure and arguments of
each call against a reference call~\cite{patil2024gorilla,patil2025bfcl}. Free text is scored by an
LLM judge: Zheng \textit{et~al.} found that a strong judge agrees with human experts about as often as humans
agree with each other (85\% versus 81\% on MT-Bench expert votes without ties) and named position and verbosity
biases~\cite{zheng2023judging};
Panickssery \textit{et~al.} showed that LLM evaluators recognize and favor their own
generations~\cite{panickssery2024llm}; G-Eval has the judge reason before filling a scoring
form~\cite{liu2023geval}. Two works shape the automated calibration used here: CheckList's invariance and
directional-expectation tests~\cite{ribeiro2020beyond}, and Doddapaneni \textit{et~al.}, whose targeted
perturbations showed that evaluator LLMs missed quality drops in over half of the cases~\cite{doddapaneni2024finding}.
For statistics, Dror \textit{et~al.} give a protocol for choosing significance tests and note that the
Wilcoxon signed-rank test~\cite{wilcoxon1945individual} is applicable to most NLP setups~\cite{dror2018hitchhikers}; Holm's
procedure controls the family-wise error over several hypotheses~\cite{holm1979simple}; the bootstrap gives
confidence intervals~\cite{efron1993introduction}; the rank-biserial correlation is the matching effect
size~\cite{kerby2014simple}; and weighted kappa measures agreement on ordered levels~\cite{cohen1968weighted}.

\section{System Overview}\label{sec:system}
Fig.~\ref{fig:arch} shows the architecture. The car is a small differential-drive robot: a Raspberry Pi Pico~2~W
(RP2350) runs micro-ROS over Wi-Fi, drives two 1:90 TT gear motors with Hall quadrature encoders through a
TB6612FNG driver, and reads a BNO055 inertial measurement unit; an ESP32-CAM (OV3660) serves JPEG frames over HTTP.
The host is an NVIDIA DGX Spark (GB10, 128\,GB unified memory) running the \texttt{beaconmind-ros} container
(ROS~2 Humble), with a kinematic simulator for fast experiments and an Isaac Sim~5.1 digital twin that is planned
but not built yet. The code is at \url{https://github.com/XiaohuiChen-personal/en665715-beaconmind}.

\input{fig_architecture}

\textbf{One step.} The car moves only in five bounded moves (0.25\,m or 0.10\,m forward, 0.10\,m back, $\pm30^\circ$
turns) and stops after each. At every stop the harness sends the agent a step message: the mission, an
operator request (usually none), the \emph{observation} (the odometry increment since the last stop, the tag
detections with ID, range, bearing and quality, harness counters, and safety flags computed by the validator),
and the agent's own previous report, which is its only memory. The agent runs a ReAct loop: it reasons, calls
tools (Table~\ref{tab:tools}), reads their results and repeats, then returns one JSON report with its pose,
the source of that pose (beacon fix, relocalization, position fix, kept prior or odometry), its associations, loop closures,
map, bookkeeping memory, decision and a one-sentence \emph{note} for the operator. In closed loop the validator
executes the decided move; in replay the move is the logged one and the agent only estimates.

\input{tab_tools}

\textbf{Who decides what.} The system prompt (v3.3; 4,352 tokens as counted when it was written for a Qwen model)
states a per-step procedure: predict the pose
from odometry; gate each detection against the map entries with the same ID; correct the pose from matched,
confirmed beacons; add new beacons as tentative and confirm them after two sightings over a 0.40\,m baseline;
accept a loop closure only inside a full beacon fix; and choose the next move. The tools return every number
and flag; the agent decides which results to accept and writes the state. When two physical tags share an ID,
a detection far from the existing beacon of that ID becomes a second beacon labeled \texttt{B<id>b}.

\textbf{Safety.} The design has three layers: an out-of-band STOP that aborts any move, disables the motor driver
and sets a persistent latch; the validator of Table~\ref{tab:tools} together with the Pico's watchdog and stall
detection; and the agent's own guardrails (never move on an error, refuse requests outside the missions, ask when a
target is ambiguous). Today the car runs lab firmware with a watchdog, a deadman and a stall cut-off; the project
firmware and the latching STOP are planned.

\textbf{Runtimes.} The benchmark uses a minimal harness that exposes only the nine tools, because ROSA adds 47
tools and nine fixed prompts (about 6,000 Qwen tokens) to every call, which would confound model comparisons; ROSA
(1.0.10) is the demonstration runtime, with the same tools.

\section{Experiments}\label{sec:experiments}
The experiments below are the plan for the full study; the pilot that informed them is described in the past
tense in Sections~\ref{sec:procedure} and~\ref{sec:results}. The hypotheses, metrics and analysis were written
on 2026-10-29, before any held-out data were collected; development uses seeds 1000--1099 and the confirmatory
runs use seeds 2000--2199, which no model has seen. The project plan's pre-registration (task M4.T1), which does

\subsection{Research Questions and Hypotheses}\label{sec:rq}
The arms are B0 (dead reckoning), B1 (a factor-graph reference), B2 (the per-step procedure written as code, the
\emph{coded procedure}) and L2 (the LLM agent); Table~\ref{tab:config} lists them.

\textbf{RQ1 (primary): estimation.} Replay on held-out simulated logs with duplicated tag IDs.
\emph{H1 (primary):} the agent's ATE-RMSE is lower than dead reckoning's (B0).
$H_0$: the median per-seed paired difference (L2 $-$ B0) is $\geq 0$; $H_1$: it is $<0$; one-sided.
The smallest difference that matters is 3\,cm, one tenth of the 0.30\,m association gate: a smaller change
would not alter any association or safety decision. A significant result whose 95\,\% interval does not lie
entirely below $-3$\,cm is reported as statistically but not practically supported. Because the pilot showed
that unbiased odometry leaves no room for improvement (Section~\ref{sec:results}), H1 is tested in the 2\,\%
odometry-drift block; the no-drift block is reported as secondary.
\emph{H2 (secondary):} $H_0$: the median per-seed $\log(\mathrm{ATE}_{L2}/\mathrm{ATE}_{B1})\geq\log 2$;
$H_1$: it is $<\log 2$; one-sided. The margin of twice the reference is the plan's pre-set target.

\textbf{RQ2 (secondary): association and fidelity.} Association precision against the plan's target of 0.90,
reported separately for duplicated IDs, and tool-call F1 against the coded procedure. Descriptive.

\textbf{RQ3 (secondary): closed loop.} \emph{H3:} $H_0$: the median per-seed difference in navigation success
rate (return to start and go to a named beacon) between L2 and B2 is 0; $H_1$: it is not; two-sided. The
smallest difference that matters is 0.15, about one extra failure in seven missions.

All tests use $\alpha=0.05$ with Holm's correction over H1--H3~\cite{holm1979simple}; the no-drift H1 test and
every other metric are descriptive.

\textbf{Environment.} Simulation: a $2.25\times2.25$\,m walled arena with 12--16 AprilTag 36h11 beacons on the

\subsection{Metrics and Ground Truth}\label{sec:metrics}
Every metric is reported on a 0--1 scale where possible, with the raw value alongside.
\begin{itemize}
\item \textbf{Pose (primary):} the absolute trajectory error as a root-mean-square (ATE-RMSE) over all steps,
$\sqrt{\tfrac{1}{T}\sum_t\lVert\hat p_t-p_t\rVert^2}$, in the map frame fixed at the start pose, with no
alignment fitted; score $\max(0,1-\mathrm{ATE}/0.25\,\mathrm{m})$, where 0.25\,m is one forward move: an error
that large can put the car a whole move away from where it believes it is. Secondary: final position and heading
error, heading RMSE.
\item \textbf{Map:} an entry is correct if a tag with the same ID lies within 0.30\,m (the association gate);
otherwise it is a phantom. Reported: RMSE over correct entries, ID precision and recall.
\item \textbf{Association:} every detection is scored. A match to an existing beacon is a true positive if that
beacon was created from the same physical tag and a false positive otherwise; a detection of an already mapped
tag that is labeled new, ambiguous or rejected, or left out, is a false negative. Precision is primary, because a
false loop closure has no optimizer to absorb it.
\item \textbf{Tool-call precision, recall, F1:} gold calls are the calls the coded procedure makes on the same
observation and previous report the agent received. A predicted call matches a gold call if the tool name, the
detection index, the beacon label and the candidate or match sets are equal, the odometry arguments are equal, and
every pose argument agrees within 0.011\,m and 0.11$^\circ$ (reports round positions to two decimals and headings
to one); matching is one-to-one, micro-averaged per seed.
\item \textbf{Validity and safety gates:} the share of parseable reports with a numeric pose and a well-formed map;
an invalid report is replaced by the last valid one, dead-reckoned (counted). In closed loop, any executed move
after an emergency stop or into a refused direction fails the episode.
\item \textbf{Navigation (closed loop):} success decided from ground truth at DONE (start: within 0.30\,m; beacon:
within the 0.55\,m stop range plus 0.15\,m and $25^\circ$), and SPL~\cite{anderson2018evaluation}; refusal rate on
a fixed suite of $\geq$30 unsafe and $\geq$10 valid operator requests written before the runs.
\item \textbf{Note rubric:} the one-sentence note has no single right answer, so it gets a rubric. \emph{Faithful}
(weight 0.40): 0~=~asserts an event that did not happen or the wrong pose source; 1~=~every event real but one
detail wrong (a label, or a number beyond rounding); 2~=~all supported. \emph{Coverage} (0.25): 0~=~omits two or
more of the step's map events (new, rejected or confirmed beacons, loop closures); 1~=~omits one; 2~=~omits none.
\emph{Uncertainty} (0.25): 0~=~does not say how the pose was obtained; 1~=~says how, without a reason or quality
figure; 2~=~gives both. \emph{Concise} (0.10, scored by code): 2~=~one first-person sentence of at most 45 words;
1~=~at most two sentences and 60 words; 0~=~otherwise. Score $\sum_i w_i g_i/2$; faithfulness 0 gates the note
to 0. The judge sees what the agent saw and did (the procedure's rules and thresholds, the observation, both maps,
every tool call with its result, the report; the beacons' last-seen odometer is still missing) but never the
ground truth.
\item \textbf{Cost:} latency per step (median and 95th percentile; the closed-loop gate is a 95th percentile
$\leq$ 60\,s), tokens and US dollars.
\end{itemize}
\textbf{Ground truth.} In simulation the true pose and the true tag behind every detection are recorded at every
step, so pose and association labels carry no noise beyond the 2-decimal rounding of reports (0.005\,m,
0.05$^\circ$). Gold tool calls come from code, not from people. On the car, an overhead camera tracking a roof
tag will give the pose, accepted only if it is within 5\,cm and 3$^\circ$ of tape-measured checkpoints; each tag
position is taped twice, and the difference estimates label noise. Because 5\,cm exceeds H1's 3\,cm threshold,
real-car logs measure the sim-to-real gap descriptively and do not test H1. All labels are frozen, by file hash,
before scoring.

\textbf{Judge calibration without hand labels.} By the author's choice the pipeline is fully automated, so the
judges are not calibrated against the author's own scores; four automated checks take that place. (i)
\emph{Known-label notes:} code assembles notes from a real step's evidence with controlled defects (a missing pose
reason, one or two omitted events, a wrong label, an injected false claim), so every expected level is known by
construction; the steps chosen are those where the agent's report agrees with the procedure, so the evidence is
unambiguous. (ii) \emph{Directional test:} a false claim appended to 40 real notes must drive faithfulness to 0.
(iii) \emph{Invariance:} a repeat run, reversed anchor order and a neutral padding sentence must leave the levels
unchanged. (iv) \emph{Agreement} between the two judges, both from model families other than the agent's to avoid
self-preference~\cite{panickssery2024llm}; this check is descriptive. A judge is used only if, on the calibration
seeds 1001--1004 (held out from judge development), every judged criterion reaches weighted
$\kappa\geq0.6$~\cite{cohen1968weighted} and accuracy $\geq0.7$, it catches $\geq80$\,\% of injected false claims,
and $\geq90$\,\% of levels are invariant; among eligible judges the most accurate is used, ties going to the local
one. This rule was fixed in code before any judge saw pilot data.

\subsection{Experimental Procedure}\label{sec:procedure}
\textbf{Simulated replay (RQ1, RQ2).}
\begin{enumerate}
\item Freeze the prompt, tool schemas, design values, judge prompts and analysis code by SHA-256 hash.
\item For each held-out seed and drift level, generate the world and record an observation log with B2 driving
(the same log serves every arm, so every arm sees identical observations), in Isaac Sim if the twin is ready by the
freeze and otherwise in the kinematic simulator with the measured noise; every result names its source.
\item Compute B0 and B1 offline; B2's estimates come with the log.
\item Replay every log through each LLM arm ($K$ as in Table~\ref{tab:config}); the order of seeds within each
repeat is shuffled with a recorded random seed; five seeds run in parallel.
\item Log every step as one JSON line (\texttt{runs/<condition>/seed\_<n>.jsonl}): step, true pose, observation,
previous report, each tool call with its arguments and result, the raw and parsed report, validity flags,
fallback flag, tokens, latency and cost per turn. The analysis writes one row per condition, seed and arm
(ATE, final error, map and association scores, F1, validity, latency, cost).
\item Never drop a step silently: an invalid report becomes a dead-reckoned fallback and is counted; an API call
is attempted up to seven times, and a seed whose call still fails is rerun once and otherwise scored as
incomplete. A seed on which the coded procedure reaches an unimplemented branch is replaced by the next seed, and
the replacement count is reported.
\item Score with the analysis script, then run both judges on every note and the calibration sets.
\end{enumerate}
\textbf{Sample size.} Thirty held-out seeds per drift level; the pilot-based power estimate is in
Section~\ref{sec:stats}. An episode ends at the coded procedure's DONE or at the 150-step budget.
\textbf{Closed loop (RQ3)} runs EXPLORE, then RETURN\_TO\_START, then GO\_TO\_BEACON on 30 kinematic-simulator seeds
($K=3$), with Isaac Sim on a 10-seed subset. \textbf{Real car} (at least ten logs, replayed through every arm):
\begin{enumerate}
\item Fit the motor driver's standby pull-down resistor and pass the wheels-down gate on the bench with the wheels
up (STOP within 0.2\,s, watchdog, stall detection); clear the floor.
\item Before each episode, measure the battery pack (replace below 5.5\,V); record the light level; start the
Wi-Fi ping log.
\item Place the car on the taped start pose; start the overhead camera and the observation log.
\item Let the coded procedure (or the operator) choose the moves; the operator keeps the out-of-band STOP in hand.
\item End on DONE, the step budget, an emergency stop or a lost link (counted as aborted); save the log and the
overhead video; reset.
\end{enumerate}

\textbf{Pilot.} On 2026-10-29 I ran the replay procedure on development seeds 1000--1004 in the kinematic simulator,
with Claude Opus 5.5 as the only LLM arm and $K=1$, in two conditions: no drift (\stepsNom{} steps) and 2\,\% drift
(\stepsDrift{} steps), in total US\$\costNom{} and US\$\costDrift{}. It changed the plan in six ways:
\begin{enumerate}
\renewcommand{\labelenumi}{(\roman{enumi})}
\item odometry drift became a blocked factor and H1 moved to the drift block (Section~\ref{sec:results});
\item the judges' evidence was extended: with only the tool results and report fields, the selected judge rated
\vOneFaithZero{} of \vOneN{} real notes unfaithful, mostly for quoting facts the agent had but the evidence lacked
(the 0.40\,m confirmation baseline, turns since the last fix, beacon states), and both judges were re-run;
\item prompt caching is always on (the uncached Opus runs of 2026-10-07, on the plan's one-step test scenarios,
used about 54,000 input tokens per decision, about US\$0.25 at list prices);
\item the Gemma judge's default thinking (about 1,900 tokens and 70\,s per note) was turned off (72 tokens, 5\,s);
\item a lock stops two runs from writing the same log;
\item the coded procedure's unimplemented branches (mostly relocalization and an exploration leg with no forward
move), which stopped \sweepFailTwo{}, \sweepFailThree{} and \sweepFailFive{} of 100 development seeds at 2, 3 and
5\,\% drift, must be implemented before larger drift levels are studied.
\end{enumerate}
The pilot harness did not yet correct reported states against tool results, so the step counters that widen the
association gate reset on the agent's own claimed fixes.

\subsection{Statistical Analysis Plan}\label{sec:stats}
\textbf{Descriptive.} For every arm and condition: median and mean over seeds with 95\,\% percentile-bootstrap
intervals (10,000 resamples)~\cite{efron1993introduction}, the worst seed, and a plot of the per-seed points; with
five seeds (the pilot) the median and range are reported instead, since such intervals under-cover.
\textbf{Tests.} The unit is the seed (repeats averaged). H1 and H2: one-sided Wilcoxon signed-rank tests on the
paired per-seed differences and log ratios~\cite{wilcoxon1945individual}, chosen because the differences are
paired, few and not assumed normal~\cite{dror2018hitchhikers}; the test assumes differences symmetric about their
median, which is checked on a plot, and a sign test replaces it if they are clearly skewed. H3: two-sided
Wilcoxon on per-seed success rates, with an exact McNemar test on the first repeat as a check. Effect sizes: the
matched-pairs rank-biserial correlation~\cite{kerby2014simple}, the median difference with its interval, and
Cohen's $d_z$. Holm's correction over H1--H3 at family-wise $\alpha=0.05$. No outlier is removed; fallbacks stay in.
\textbf{Power.} The one-sided Wilcoxon test at $\alpha/3$ is simulated on per-seed differences drawn from a normal
distribution with the pilot's standard deviation, at the pilot's mean and at the 3\,cm threshold
(Section~\ref{sec:results}); if 30 seeds give less than 0.8 power, the report will say H1 is underpowered. The
3\,cm threshold enters only the power analysis and the interpretation of H1, not the test itself.
\textbf{Held out.} The prompt (v3.3) was finished on 2026-09-27 on one-step test scenarios before any pilot seed
existed; the tools, the simulator and the judge rubric were developed on seeds 1000--1099, and the rubric, anchors
and selection rule were fixed before the calibration runs. Two later changes were made
while looking at pilot items: Gemma's thinking was turned off for speed, and the judges' evidence was completed
after reading flagged real notes, so the pilot's rubric scores are not held out; known-label calibration is
reported on seeds 1001--1004, with seed 1000's items kept as a development set. \textbf{What would change my mind.} If the agent's ATE stays within 1\,cm of B2's on every seed, the
model adds no estimation value beyond the code it executes, and any value of BeaconMind lies in its notes,
questions and refusals; if it does not beat B0 under drift, an LLM-owned estimate is not competitive at this
scale.

\subsection{Confounding Variables and Threats to Validity}\label{sec:confounders}
\begin{itemize}
\item \textbf{World layout and tag placement:} paired, every arm sees the same seeds; seeds drawn from a generator
that enforces the arena rules.
\item \textbf{Odometry drift:} blocked at two levels and reported separately.
\item \textbf{Detector noise model:} fixed within a phase; placeholder, Isaac-rendered and real noise are reported as
separate sources.
\item \textbf{LLM sampling variability:} $K=3$ repeats per seed; the API's default sampling, recorded.
\item \textbf{Model and API version:} the served model name is logged on every turn, all runs fall in one dated
window, and the prompt and tool schemas are hashed.
\item \textbf{Path and episode length:} in replay every arm sees the B2-driven path; closed-loop results are reported
separately because the path then depends on the model.
\item \textbf{Real car:} battery voltage (measured before each episode), Wi-Fi stalls (ping logged; lost links counted),
lighting and floor (one room, recorded).
\end{itemize}
\textbf{Threats.} \emph{Internal:} gold tool calls come from the agent's own specification, so tool-call F1
measures fidelity to the procedure, not correctness of the procedure; the pilot has five seeds per condition;
Claude Opus~5.5 helped write the procedure, the prompt and the harness and is also the agent under test, which may
favor it when other models join; latency was measured with five seeds running in parallel.
\emph{External:} one arena size, one tag family, a placeholder detector model that computes visibility from the
axle instead of the camera and spaces some neighboring tags up to 0.84\,m apart (the design rule is 0.8\,m), one
car and one room; the two copies of a duplicated ID are at least 1.5\,m apart while the gate is at most 0.6\,m, so
the pilot's duplicates were easy to tell apart, and a harder condition with copies inside the 1\,m conflict
radius is needed.
\emph{Construct:} ATE in a start-anchored frame mixes heading and position error; the note rubric measures report
quality, not estimation; known-label notes are written by code and are easier to read than real notes.

\textbf{RQ1, estimation.} Without odometry drift, dead reckoning was the most accurate arm on every seed (median
ATE \ateBZeroNom{}\,cm, Table~\ref{tab:pilot}); the agent's error (median \ateLTwoNom{}\,cm) stayed within about
\lTwoBTwoNom{}\,cm of the coded procedure's on every seed. The paired difference, agent minus B0, averaged
$+$\hOneMeanNom{}\,cm (95\,\% bootstrap interval \hOneLoNom{} to \hOneHiNom{}\,cm), so H1 is not supported in this
block: in a 2.25\,m arena, landmark fixes built from noisy ranges appear to add more error than unbiased odometry
accumulates.
With a 2\,\% systematic over-read the order reversed (Fig.~\ref{fig:pilot}a): the agent beat dead reckoning on all
\hOneNegDrift{} seeds, with a mean difference of \hOneMeanDrift{}\,cm (\hOneLoDrift{} to \hOneHiDrift{}\,cm), a
rank-biserial correlation of \hOneRDrift{} and an exact one-sided Wilcoxon $p=\hOnePDrift$. That is the smallest
value five pairs can give, and it cannot reach Holm's first threshold ($\alpha/3\approx0.017$), so the pilot could
not show significance by design. The gain was uneven across seeds (Table~\ref{tab:pilot} ranges) and its mean is
below the 3\,cm that matters, so no practical claim is made. Fig.~\ref{fig:pilot}b explains the reversal: over 100
development seeds, the coded procedure's median error falls below dead reckoning's between 0.5 and 1\,\% drift,
it is ahead on most seeds only from 1.5\,\%, and it is ahead on \sweepWinTwo{} of the \sweepNTwo{} seeds that
completed at 2\,\%.

\textbf{RQ2, association and fidelity.} The agent chose the same pose source as the procedure on every step and the
same association decision for every detection; the only difference was that it named the nearest candidate of a
rejected detection, where the procedure leaves the label empty. It made every gold tool call (recall
\recallNom{} and \recallDrift{}); its precision (\precNom{} without drift, \precDrift{} with drift) reflects
\callsUnmatched{} extra calls out of \callsTotal{}: \fpFixRefused{} \texttt{fix\_pose} calls without a confirmed
beacon, which the tool refused; \fpGateEmpty{} \texttt{gate\_detection} calls with no candidate, used only to obtain
the new point; \fpExplore{} \texttt{exploration\_summary} calls that replay does not need; \fpMove{} \texttt{move}
calls, all refused in replay; and \fpOther{} others. Association precision was 1.00 for both arms in both blocks,
duplicated IDs included, but the copies were far apart (Section~\ref{sec:confounders}), so this is weak evidence;
recall fell under drift for both arms nearly equally, probably because drifted priors push re-sightings out of the
gate, and under drift each arm ended with \phantomsDrift{} phantom map entries over the five seeds.

\textbf{Validity and cost.} All reports were valid, with no fallback and no emergency stop. The 95th-percentile
latency per step was at most \latNom{}\,s without drift and \latDrift{}\,s with drift, below the 60\,s gate. The
agent's API calls cost US\$\costNom{} and US\$\costDrift{} for the two blocks (per step in Table~\ref{tab:pilot});
the GPT-6.1 Sol judge runs cost a further US\$\judgeCostVOne{} and US\$\judgeCostVTwo{}.

\textbf{Note rubric and judges.} Table~\ref{tab:judge} shows the automated calibration. GPT-6.1 Sol met every
threshold and was selected. Gemma~4 26B caught every injected false claim but agreed poorly with the key on
coverage (weighted $\kappa$ \klKappaCoverGemma{}), mostly by missing a single omitted event, so it was not
eligible. Scored by Sol, the per-seed median rubric score was \rubricNom{} without drift and \rubricDrift{} with
drift, and \gateNom{} and \gateDrift{} notes failed the faithfulness gate. The evidence mattered more than the
judge: with the first, incomplete evidence the same judge had marked \vOneFaithZero{} of \vOneN{} notes
unfaithful, with the extended evidence \vTwoFaithZero{}, and that one failure quotes the beacons' last-seen
odometer, a field the evidence still omits. The synthetic notes, built only from facts inside the evidence, could
not reveal that gap; reading the real notes did. No note named a beacon label absent from its report (the code
cross-check). Gemma scored only \gemmaRealN{} real notes (\gemmaRealDriftN{} with drift) before it was stopped; on the
\interN{} notes both judges scored, they gave the same faithfulness level to a share of \interExactFaith{}, but
almost every note is at level~2, so the weighted $\kappa$ (\interFaith{}) says little.

\textbf{Power.} Resampling the five drift-block differences gives a power of 1 already at ten seeds, an artifact of
five values that are all negative. Under the normal model with the pilot's standard deviation (\sdDrift{}\,cm), 30
seeds give a power of \PowObsThirtyDrift{} at the observed mean and \PowSesoiThirtyDrift{} at the 3\,cm threshold.
That standard deviation comes from five skewed values (95\,\% interval \sdLoDrift{} to \sdHiDrift{}\,cm); at the
upper end the power at the threshold falls to \PowSesoiSdHiDrift{}, so 30 seeds per block is a floor, to be
re-checked on the full pilot. Because the agent tracked the coded procedure within a few millimeters, the main
study must also ask what the LLM adds beyond the code it executes (Section~\ref{sec:stats}).

\section{Conclusion}\label{sec:conclusion}
The pilot shows, provisionally, that a frontier LLM can carry out a landmark-SLAM procedure step by step through
tools with near-perfect fidelity: every report was valid, every pose source and association decision matched the
procedure, and association precision stayed at 1.00 with duplicated tag IDs. It also shows the limit of that result.
The agent was as accurate as the code it emulated (within \lTwoBTwoNom{}\,cm): worse than dead reckoning when
odometry was unbiased, and better when odometry drifted by 2\,\%. These findings rest on five development seeds per condition, one model, one
repeat, a placeholder noise model, no factor-graph reference and no closed loop, so they are not claims.

In the remaining weeks I will measure the camera and odometry noise on the car and implement the procedure's missing
relocalization branch; build the factor-graph reference and the closed-loop harness; run the confirmatory replay on
30 held-out seeds per drift block, with three repeats for a local model and Claude Opus 5.5 within a sweep budget
still to be set; record and replay at
least ten real-car logs; and test conditions in which the procedure alone is not enough, such as hidden tag IDs and
operator requests, to learn whether the language model adds value beyond executing the code it is given.
