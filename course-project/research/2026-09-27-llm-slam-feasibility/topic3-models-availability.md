SUMMARY: All four frontier models the student named exist and can be called as tool-using, image-reading agents as of 2026-09-27. They are all reasoning models, though, and that shapes how the benchmark has to work. OpenAI's API docs list GPT-6 Astra (`gpt-6-astra`, released Sep 3, 2026, $10/$50 per MTok) and GPT-6 Sol (`gpt-6-sol`, released Sep 22, 2026, $2/$10). There is also a cheaper third tier, GPT-6 Luna (`gpt-6-luna`, $0.10/$0.50). All three accept text and image input, support function calling, and have a 1.05M-token context window with 128K max output. Astra has no `none` reasoning effort, so its lowest setting is `low`. Anthropic's docs list Claude Opus 5.5 (`claude-opus-5-5`, released Sep 22, 2026, $4/$20) and Claude Fable 5.1 (`claude-fable-5-1`, released Sep 1, 2026, $10/$50). Both take text and images, use tools, have 1M context and 128K output, and have thinking always on. Both reject forced `tool_choice` (`any`/`tool`) and non-default sampling settings; the no-custom-temperature rule is verified for Fable 5.1, and for Astra it comes from a paraphrase. Artificial Analysis measures time-to-first-token (TTFT, the wait before any output appears) of about 6 s for Opus 5.5 and Fable 5.1 at low effort. It measures about 36 s for Sol at xhigh and about 98 s for Astra at xhigh, and minutes at max effort. On the local side, Qwen3.5-35B-A3B, Qwen3.6-35B-A3B and Qwen3.8-27B are Apache-2.0 native vision-language models. Gemma-4-26B-A4B-it supports images and native function calling with a `gemma4` vLLM tool parser. Published DGX Spark decode speeds are roughly 21–30 tok/s for Qwen3.6-35B-A3B-FP8 on vLLM, about 24.5 tok/s for Qwen3.8-27B on vLLM (34–38 on SGLang with speculative decoding), and about 52 tok/s for Gemma 4 26B-A4B NVFP4. Dense 31B Gemma runs at about 7 tok/s. NVIDIA's official Spark figures are 128 GB unified memory and 273 GB/s bandwidth. GLM-5.3-Flash (320B total) and Qwen3.8-2.4T-A95B are open-weight but too large for one Spark. I could not verify a 2026 Llama or a current general-purpose InternVL release from official sources.

IMPLICATIONS:
- INFERENCE: The student's model names are right, with small fixes. The API IDs are gpt-6-astra, gpt-6-sol, claude-opus-5-5 and claude-fable-5-1. GPT-6 Luna ($0.10/$0.50) is a cheap, low-latency OpenAI tier worth adding as a baseline. Claude Sonnet 5 and Haiku 4.5 play the same role on the Anthropic side.
- INFERENCE: Latency rules out continuous closed-loop control by any frontier model. Measured TTFT runs from about 6 s at low effort (Opus 5.5 / Fable 5.1) to minutes at max effort, and Astra has no 'none' effort. The design must be stop-perceive-think-act: the robot halts, the model returns one bounded move, and the Pico runs it. This matches the rule that the LLM stays out of the motor loop. The benchmark should fix the effort level per model and report wall-clock per decision and per episode alongside accuracy.
- INFERENCE: Sampling can't be made deterministic. Fable 5.1 rejects non-default temperature/top_p/top_k, and Astra reportedly disallows custom temperature/top_p. So temperature=0 is not an option: run N≥3–5 trials per condition and report mean and variance.
- INFERENCE: The harness needs a provider abstraction. Opus 5.5 and Fable 5.1 reject forced tool_choice, so use tool_choice auto plus strict: true schemas and count a turn with no tool call as a logged failure or retry. Astra reportedly requires the Responses API for tool calls. Local models run through vLLM's OpenAI-compatible endpoint with the qwen3_coder or gemma4 tool parsers.
- INFERENCE: Preserved thinking on Opus 5.5 and Fable 5.1 conflicts with the natural 'LLM as SLAM' design of rewriting a map summary in the system prompt every step. For accounts created after Aug 31, 2026 that returns 400 errors. There are two options. The first is stateless per-step calls: a fresh conversation each step, with the serialized beacon map, pose belief and new observation as the only input. This is also the fairest way to compare models. The second is strictly append-only conversations with state updates delivered as new messages.
- INFERENCE: Anthropic's docs describe Claude's coordinate and localization outputs as approximate. So the benchmark should separate two roles. (a) A classical AprilTag detector front-end (tag ID, range, bearing from the known tag size and camera intrinsics) feeding the LLM, which does the estimation, data association and loop closure. (b) A raw-image VLM variant, run as an ablation. Without that split, a model's failure to measure pixels can't be told apart from a failure at SLAM reasoning.
- INFERENCE: Image input is cheap. A 640×480 ESP32-CAM frame is ceil(640/28)×ceil(480/28) = 23×18 = 414 Claude visual tokens, about $0.0017 per frame on Opus 5.5. Output reasoning tokens will dominate cost. As a rough example, 200 steps × (5k in + 2k out) comes to about $30 per run on Fable 5.1 or Astra, about $12 on Opus 5.5, about $6 on Sol and about $0.20 on Luna, before caching or batching.
- INFERENCE: For local models, decode speed of about 20–50 tok/s on the Spark means a 1–2k-token thinking trace costs 40–100 s per step. Run local models with thinking off or at low reasoning effort, cap output tokens, and prefer MoE models (Qwen3.6-35B-A3B, Gemma-4-26B-A4B) over dense ones. Qwen3.6-35B-A3B supersedes the cached Qwen3.5-35B-A3B at the same size, with better vendor-reported RefCOCO and EmbSpatial scores. It is worth adding.
- INFERENCE: Some models don't fit a single 128 GB Spark: GLM-5.3-Flash at 320B total (roughly 160 GB or more even at 4 bits) and Qwen3.8-2.4T. Reasonable local candidates are Qwen3.5/3.6-35B-A3B, Qwen3.8-27B (FP8 or NVFP4), Gemma-4-26B-A4B, GLM-4.6V-Flash 9B (it has native grounding), possibly Llama 4 Scout at Int4 (2025 vintage), and gpt-oss-120b as a text-only 'SLAM back-end' baseline fed detector output.
- INFERENCE: Handling safety refusals and fallbacks matters for the benchmark. Anthropic's server-side fallbacks retry refused requests on a different model, which would silently contaminate per-model results. Either disable fallbacks in benchmark runs or log the model that actually answered and the stop_reason on every call.
- INFERENCE: Vendor-reported embodied/spatial scores (ERQA, EmbSpatialBench, RefCOCO) are useful for picking candidates but don't show landmark-SLAM ability. The student's own sim and real benchmark is the actual measurement.

CHALLENGES:
- LATENCY (partly wrong): 'measured TTFT runs from about 6 s at low effort' is only true for the Claude models and the asymmetric AA pairings picked. Artificial Analysis reports GPT-6 Sol (Non-reasoning) at 1.10 s TTFT (https://artificialanalysis.ai/models/releases/gpt-6-sol) and GPT-6 Luna (low) at 2.16 s TTFT (https://artificialanalysis.ai/models/gpt-6-luna-low). The frontier floor is therefore about 1–2 s, not 6 s. Only Astra (minimum 'low'), Opus 5.5 and Fable 5.1 (thinking always on) cannot go to zero reasoning. Stop-perceive-think-act is still the right design, but comparing Claude at low with GPT at xhigh/max makes OpenAI look much slower than it has to be. The benchmark should compare at matched effort tiers. AA's TTFT includes thinking time on AA's own text prompts, not image+tool prompts, so it is only a loose proxy.
- DETERMINISM (overstated): 'temperature=0 is not an option' holds for Opus 5.5, Fable 5.1 and Astra. OpenAI's GPT-6 guide says only 'When reasoning effort is not `none`, remove `temperature`, `top_p`...' (https://developers.openai.com/api/docs/guides/latest-model.md), so Sol and Luna at effort none, and all local vLLM/Ollama models, do accept temperature. Temperature is thus a confound between providers, not something none of them allow. Repeated trials (N>=3–5) are still correct, because temperature 0 was never deterministic anyway.
- HARNESS (incomplete): the Responses-API requirement is not Astra-only. Sol and Luna 'support function calling in Chat Completions only with `reasoning_effort: "none"`. Use Responses for reasoning with tools.' (https://developers.openai.com/api/docs/models/gpt-6-sol.md). Any OpenAI tool-calling run with reasoning on must go through Responses. Qwen3.8-27B uses the `qwen3_xml` parser, not qwen3_coder (https://recipes.vllm.ai/Qwen/Qwen3.8-27B).
- PRESERVED THINKING (partly overstated): 'rewriting a map summary in the system prompt every step ... returns 400 errors' only applies if you replay earlier thinking blocks inside the same conversation. The fully stateless per-step design avoids it completely. Anthropic also documents an append-only route: mid-conversation system messages, plus turn-scoped system messages (`clear_at: "next_user_message"`) on Fable 5.1, or `prefix_mismatch_behavior: "drop_block"`. The researcher's two options are fine but not the only ones.
- FALLBACK CONTAMINATION (overstated): server-side fallback is opt-in. You must set `fallbacks` ("default" or a list) and send the `server-side-fallback-2026-07-01` beta header. The response 'names the model that served it' through the top-level `model` field and a `fallback_message` entry in usage.iterations (https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback). It is not silent unless the student turns it on and never logs `model`. Logging `model` and `stop_reason` is still good practice. Artificial Analysis's own Opus 5.5 numbers carry a 'Default Fallback' label, so third-party latency figures may themselves be fallback-mixed.
- COST ARITHMETIC (small error): at $0.10/$0.50, Luna comes to 200×(5000×0.1+2000×0.5)/1e6 = $0.30, not $0.20. The Fable 5.1 and Astra ($30), Opus ($12) and Sol ($6) figures check out. The Claude image token count (23×18 = 414 tokens, about $0.0017 on Opus 5.5) is correct. OpenAI's image cost for Astra is different: 32-px patches × 1.2 multiplier, so 640×480 is 20×15 = 300 patches, about 360 tokens (https://developers.openai.com/api/docs/guides/images-vision.md).
- LOCAL LATENCY (minor): '1–2k-token thinking trace costs 40–100 s' at 20–50 tok/s is actually 20–100 s. Qwen3.8-27B thinks at xhigh by default, so enable_thinking must be set to false explicitly. The Gemma 31B '7 tok/s' figure is BF16, not NVFP4, so 'prefer MoE' is right but overstated for a quantized dense model.
- MODEL FIT (unverified leap): 'GLM-5.3-Flash does not fit a single Spark' is right at 4 bits (about 160 GB), but the card lists 122 community quantizations. A roughly 2–3-bit GGUF might fit in 128 GB. Mark it 'unverified; likely impractical' rather than impossible.
- CANDIDATE LIST (stale): 'possibly Llama 4 Scout at Int4 (2025 vintage)' ignores Meta's Aug 2026 open-weight VLM Muse Glimmer 30B, which is vLLM-verified on DGX Spark, as the stronger Meta candidate. Qwen3.5-35B-A3B is not Spark-verified in vLLM recipes; Qwen3.6-35B-A3B and Qwen3.8-27B are.
- ANTHROPIC-SIDE BASELINES: calling Sonnet 5 and Haiku 4.5 cheaper baselines is supported ($2/$10 'Fast'; $1/$5 'Fastest'). Sonnet 5's thinking is 'Adaptive' but not listed as always-on, and Haiku 4.5 uses extended (manual) thinking, so both can likely run without thinking. Of the four Claude models, those two are the only ones where a low-latency no-thinking run is plausible. That is an inference from the models table and was not directly tested.
